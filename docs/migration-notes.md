# 迁移说明（migration notes）

## 变更摘要
7 个 ini 全部修改：自建 token 修正（N转直/北场IX/F北转 进入过境北场；商业池全面排除自建）、
interval 调整（灾备 600 / 大流量 900）、gocn 悬空引用修复、general 重复定义修复。
组名/组数/类型/嵌套/规则目标零变化。
北场L/XX-L 纯落地**保留在池中**（初版曾排除，已按用户澄清撤回）：dialer-proxy 前置由下游客户端覆写添加，
落地节点在自动池中的存在不变。

## 行为变化点（部署后用户可见）
1. **普通灾备池**不再含自建双角色节点：灾备 fallback 只在商业节点间选择（原设计意图，此前是漏进来的）。
2. **过境低延**变纯商业：微软公共/美国公共/微软云盘默认路径从此只会选商业节点——这正是防送中的设计目标。
3. **过境北场**新增 N转直/北场IX/F北转 成员：过境链自建优先段覆盖面恢复完整。
4. 灾备掉线切换频率下降（300→600s）：故障感知延迟变长，属预期。
5. general 的 学术直连 组恢复长定义（手动切换/低价区/各国节点 选项回来）；默认仍 🚄 本地直连。
6. gocn 的 回国节点 菜单恢复 🐉 回国灾备 可选。
7. 落地节点（北场L/XX-L）照常出现在各国灾备/低延池——它们靠下游覆写的 dialer-proxy 走自建前置，
   无需本仓库排除。若下游覆写未生效，落地会被直连使用（线路差），属下游配置责任。

## 回滚
单分支 `refactor/proxy-group-topology`，`git revert` 或切回 main 即可；无数据/订阅端状态迁移。

## 部署验证步骤
1. subconverter 转换任一变体 URL，确认 HTTP 200 且 YAML 可解析。
2. 在 Sparkle 导入 manual 变体，检查组树：过境北场应含 N转直；美国灾备应不含 自建双角色节点（N转直/北场D）。
3. 观察一个探测周期：连接面板里 N转直 节点应无后台测速记录（灾备/低延/过境低延均已排除）。
4. 回家/WHS 组行为不变：30s 探测照旧。

## 遗留（后续阶段）
- dialer-proxy 链式：由**下游客户端覆写**实现（落地节点 → 过境北场地区组作为前置）；本仓库组拓扑保持稳定命名挂点。
- rule-update.yaml 的 AND 端口风暴折叠（1767→131）。
- convertlist2yaml 跳过 MANUAL 中间产物；清理 13.1MB 孤儿 yaml。
- base 建议（tcp-concurrent 等）按 performance-analysis 清单逐项决策。
