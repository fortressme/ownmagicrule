## 质量阶梯与语义（重构前后不变）

- 选择逻辑：质量等级优先 > 同质量内延迟优先；fallback 刻意，不机械换 url-test。
- 高质组 = 一个大 fallback，成员顺序 = 订阅内顺序（高质 > 自建 > 普通），用户维护订阅顺序。
- 过境链 = 自建优先（过境北场）→ 商业兜底（过境低延）；过境/北场为反审计中性词，不得改名暴露自建。
- 自建与商业分离的边界（2026-09-19 再拍板）：**地区灾备收自建完整节点**（北场D/N转直等可直连双角色，它们本身就是完整线路+落地，是灾备的正当候选）；灾备只排除**纯过境**（北场过境）与**链组件**（LNIX）。高质灾备按订阅顺序收自建组合。
- 微软公共/美国公共默认走商业过境低延（防 bing 上报导致自建落地送中）。
- 6+1 个 ini 变体各司其职：main（白名单+自建落地）、black（黑名单漏网直连）、general（公共服务，弱化自建）、manual（手动为主，现网 Sparkle 使用中）、black-manual、manual-test（!!empty-fallback 测试）、gocn（回国/海外访问内网）。

## 重构前的问题（全部实测确认）

1. `北转` 排除词失效：机队改名 `N转直` 后，29 个（现 11 个）N转直 漏进 灾备/过境低延/低延简选（商业池混入自建）。
2. `通用过境北场`/`过境北场` include 只有 `北场D|北场专线|北场过境`，N转直/北场IX/F北转 全部缺席自建过境链。
3. gocn.ini `🐼 回国节点` 引用不存在的 `🎭 回国灾备`（实际为 `🐉 回国灾备`），且重复引用两次 → 悬空引用。
4. general.ini `📚 学术直连` 定义两次，短定义静默覆盖长定义。
5. interval 偏热：普通灾备 300s（spec 600–900）、大流量灾备 300s（89 节点，spec 900–1800）、高质灾备 300s（spec 600）。
6. main.ini 探测重复：灾备/高质灾备/过境低延/低延简选 对 LF 美国段三重覆盖；6 个过境北场组实际只有 2 个不同正则。

> 注：初版重构曾把 北场L/XX-L 纯落地从自动池排除（视作"落地不给客户端直连"），后经用户澄清撤回：
> 落地节点的 dialer-proxy 前置由下游客户端覆写解决，本仓库的组拓扑应让落地照常出现在池中。
